Consistent application icon

  • Wire the same icon into the window, the executable, the installer and update metadata.
  • A framework default, missing icon or renamed image blocks the release.

Verified update and rollback

New versions arrive quietly in the background and install only when you choose, with your work kept safe.

What it must do

  • Check at startup and on a bounded schedule, on by default, with a manual "Check for updates" command.
  • Verify feed details and package hashes over HTTPS, then stage the update without interrupting work.
  • Show a persistent, non-blocking banner with the version, release notes and an unsigned warning.
  • Restart only when the person chooses, protect unsaved work, and roll back on failure.

verifiedProof needed: Checks for no update, ready, offline, bad hash, cancellation and rollback, plus a banner screenshot.

One-click build entrypoints

Anyone can build the app or its installer from a fresh checkout with one script, and see honestly whether it worked.

What it must do

  • Root build.bat and build-installer.bat take a fresh Windows checkout to a runnable app and installer.
  • Install dependencies in user scope, report each phase, and support silent mode.
  • Pass through the real exit code; never report placeholder success.
  • Print the installer path and SHA-256, and never publish or tag.

verifiedProof needed: A silent run that exits non-zero on the first real failure, and a matching installer digest.

Bundled runtime dependencies

Everything the app needs ships inside it, so it works offline and never asks you to install something else.

What it must do

  • Ship every needed tool inside the installer; the app works with the network unplugged.
  • Say which copy is in use, and list every location searched when one is missing.
  • Never tell the person to install something and try again.

verifiedProof needed: The installed package resolving its bundled tool and reporting it as bundled.

Verified dependency acquisition

One script gathers every build tool at an exact, checked version, so builds are the same on every machine.

What it must do

  • download-dependencies.bat fetches everything needed to build, run and test.
  • Pin exact versions and verify recorded digests from a committed manifest.
  • Stay idempotent and silent-capable; exit non-zero on the first real failure.
  • Never commit fetched files or install secrets; the build scripts call it.

verifiedProof needed: Digests verified on a warm and a cold run, with no prompts in silent mode.

Required-format signing

Packages that must be signed are signed with a project key, and the release says plainly what that does and does not prove.

What it must do

  • Sign only when a format requires it, such as a browser extension package.
  • Use a project-owned key in protected storage; no paid certificate or signing service.
  • Verify the signature before release and state that it proves only key possession.

verifiedProof needed: A verified signature and no key material in the repository, logs or assets.

Windows installer lifecycle

Windows installs, updates and removals all go through one standard installer, with its limits stated up front.

What it must do

  • Every Windows installer ships Setup.exe, RELEASES, the full package and deltas where available.
  • Migrate or remove every other installer route.
  • State plainly that the files are unsigned and may trigger a publisher warning.

verifiedProof needed: The complete asset set attached to the release, with the unsigned notice in the notes.
