Useful presets for empty editors

An empty editor offers ready-made starting points built from the real defaults, so you never face a blank screen.

What it must do

  • Opens an empty editor with presets instead of a blank space.
  • Builds every preset from the real defaults, so a preset and Reset to defaults always agree.
  • States exactly what each preset creates and sets before you apply it.
  • Records applying a preset in local history, so one undo reverses it.

verifiedProof needed: Preset and reset produce the same result, and undo restores the empty state.

command-palettecontrastPartial

Command palette

One shortcut finds any command, page or setting and takes you straight to the exact control.

What it must do

  • Opens with Ctrl+Shift+F from anywhere; no competing Ctrl+K default.
  • Lists every command, page, article, setting and appearance control, with live controls in rows.
  • Jumps to the exact control: right tab, scroll position, focus and a brief highlight.
  • Shows locked items as locked and asks first instead of jumping past the lock.
  • Remembers card or full-window size; has its own pattern search.

verifiedProof needed: Every setting and page reachable by shortcut and jump, captured from the built app.

Context menus

Right-click, long-press or the menu key on any element gives the actions for that element, with a filter.

What it must do

  • Gives every element its own right-click menu, with keyboard and touch equivalents.
  • Includes Edit appearance and Lock this element on every menu.
  • Opens with a focused filter field and its own pattern tools, however short the menu.
  • Arrows move, Enter runs, Esc clears then closes, and focus returns to the opener.
  • Announces the match count and says plainly when nothing matches.

verifiedProof needed: Menus on small, disabled and state elements, each with a working filter.

guided-formscontrastPartial

Guided forms

Forms suggest valid values and can walk you through a choice step by step, without blocking the direct route.

What it must do

  • Offers real suggestions and valid defaults instead of blank boxes.
  • Checks typed and picked values the same way, inline, as you go.
  • Keeps simple choices for beginners, with a Custom state that never overwrites advanced values.
  • Offers an optional step-by-step guide with Back, Cancel and a clear result; the direct route stays.
  • Gives every editable text box its own clear button.

verifiedProof needed: The guided and direct routes save the same value through the same checks.

Contextual help for every control

A small info button above each control explains it and lets you practise safely before changing anything real.

What it must do

  • Places a small info button directly above each capable control.
  • Opens help written for that control: purpose, options, default and a worked example.
  • Includes a practice area with its own reset that never touches real data.
  • Works by keyboard, has an accessible name, and returns focus when closed.

Visible menu keyboard shortcuts

Menu items show the keyboard shortcut that really works for them, so you learn the faster route as you go.

What it must do

  • Shows each working shortcut right-aligned in the platform's own notation.
  • Reads the label from the same source that registers the key, so they cannot drift.
  • Shows nothing for items without a shortcut.
  • Announces the shortcut to screen readers once.

Independent full regex search builders

Each search box has its own pattern builder, so precise searches never disturb another search.

What it must do

  • Gives every search its own pattern builder beside it; plain text by default.
  • Keeps query, pattern, flags, mode and history separate per search.
  • Validates as you type and runs locally with a time limit.
  • Labels anything not built yet as not available rather than hiding it.

verifiedProof needed: Valid, invalid, no-match, Unicode and multiline cases on the real engine for every search.

Rich controls

Wherever a value appears, you can change it right there with the same control the settings page uses.

What it must do

  • Shows the real control wherever a value appears: rows, cells, results, cards.
  • Uses the same checks, saving, language and history as the original setting.
  • Allows a plain readout only for a named reason, with the full control one step away.
  • Keeps long lists fast and keyboard travel free of traps.

verifiedProof needed: An embedded control and its source never disagree about a value.

Settings, defaults and real consumers

Each setting says what it changes, whether it is still the default, and how to reset it.

What it must do

  • Explains what each setting does, not just its label, behind a disclosure.
  • Says whether the value is the built-in default or one you saved, and names the default.
  • Every setting has search, reset and a real place where it takes effect.
  • A written list of all settings fails a check when one has no explanation.

verifiedProof needed: The settings list check turns red for any setting without an explanation.

Complete tab navigation

Browser-style tabs keep places open side by side, pinned, grouped and remembered across restarts.

What it must do

  • Docks the tab strip to any edge, left by default, with overflow at every edge.
  • Supports reordering, pinning and named groups, kept across restarts.
  • Opens extra tabs only on an explicit New tab choice; ordinary visits reuse the main tab.
  • Closes tabs containing, or not containing, text with a preview; pinned tabs are kept.

verifiedProof needed: Every dock edge, overflow, bulk close and restart persistence, captured from the built app.
