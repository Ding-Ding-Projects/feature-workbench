Discord status integration

Lets you follow work and answer its questions from Discord, through the same inbox the Hub already uses.

What it must do

  • Read the same session status the Hub shows, and write answers into the same session inbox.
  • Keep the bridge token on the Hub host only; reading it back reports that one is saved, never its value.
  • Limit the bridge token to reading and replying, and refuse to start if it matches the worker enrolment token.
  • Name every Hub behaviour Discord cannot show, and what it shows instead.

verifiedProof needed: A Discord answer arriving through the ordinary replies route, and a refused start with a shared token.

Emergency status webhooks

Alerts the destinations the owner chose, in a fixed order, only when an emergency is verified.

What it must do

  • Send only verified emergencies, such as destroyed, intrusion attempt, reset or unavailable; suspicion alone never sends.
  • Deliver in a fixed order: Home Assistant, then Discord, then generic webhooks, with safe retries and no failure blocking the next.
  • Let only the owner register destinations; secrets stay on the host and read back as present or absent.
  • Refuse unsafe targets, redirects, oversized payloads and DNS rebinding, and send only the fixed alert fields.

verifiedProof needed: Truthful per-destination results, and checks that block forged internal targets.

Status dashboard service

Shows each project's real state in one shared place, with the evidence behind every claim.

What it must do

  • Register each project with its repository, default branch, release channel, real check results and a stable link.
  • Give the app its own status page showing what the Hub sees, with the evidence behind each claim.
  • Treat Hub rows as evidence, never intent: an answer counts as sent only once the session inbox confirms it.
  • Carry a Status Hub row in every completeness checklist, like any other feature.

verifiedProof needed: The registration visible on the Hub, inbox delivery confirmed by polling, and status page captures.

Status display integration

Shows live progress on a Tidbyt display on your desk; updates are paused for now.

What it must do

  • Paused for now: no frames are sent, and a missing frame never blocks work.
  • When resumed, send registered Tidbyt displays an animated scrolling frame with a factual progress bar for each key event.
  • Batch simultaneous events, and keep each image within the host's 32 KiB limit.
  • Show an animated idle frame at 100% when work stops, and say plainly when the Hub cannot be reached.

verifiedProof needed: A delivery receipt per event, an idle frame that moves, and every frame under the size limit.
