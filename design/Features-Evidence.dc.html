Per-surface completeness gates

Shows, surface by surface, which features are truly built, written up, translated, tested and captured.

What it must do

  • Keep one hand-written list per surface naming every feature, with links to its code, article, Cantonese copy, saved state, test and screenshot.
  • Fail the check when any row is missing, out of date or unproven.
  • Prove the check by removing one item at a time: it must turn red, then green when restored.
  • A list found automatically by scanning never counts as the inventory.

verifiedThe inventory plus a recorded red-then-green run of its check.

Preserved design source

Keeps every design file in the repository, next to the code it shaped.

What it must do

  • Commit every design file (canvas, artboards, assets, handoff notes) to the repository's own design folder.
  • Commit in the same change that creates or edits the design, even for a quick frontend-only pass.
  • Keep design files in plain English, and never call a prototype shipped behaviour.

Verified design-reference parity

Proves each built screen matches its design reference under identical capture settings.

What it must do

  • Render each reference screen deterministically by screen, state, theme, width and scale.
  • Expose a matching route in the built app for every reference.
  • List every reference once, with both routes, raw captures, a side-by-side image and diff results.
  • Fail when any reference, route, capture setting or diff record is missing or stale.

verifiedIdentical capture settings on both sides, with machine-readable diff results.

Visible build and source provenance

Tells you on the first screen exactly which version you are running and when it was built.

What it must do

  • Show the running version and its update date and time, with seconds and a named time zone, on the first screen.
  • Read both values from the build itself, never launch time, a file date or a typed label.
  • Show an honest unavailable state when the build has no record.

Verified product screenshots

Shows real screenshots of the built app, so you see what you will actually get.

What it must do

  • Capture every surface from the real built app at a known commit: main screen, dialogs, empty and error states, narrow layout and both themes.
  • Group images under collapsible headings, each with alt text saying what it shows.
  • Record commit, width, scale, theme and method for every kept image; a list of filenames is not proof.
  • Say plainly where a surface cannot be captured yet, and refresh images after any interface change.

Real workflow recording

Lets you watch a real task being done in the app before you try it.

What it must do

  • Record a real end-to-end path through the built app, not a highlight reel.
  • Capture only the app's own window on an off-screen desktop, never the whole monitor.
  • Keep it small, commit it beside the screenshots, show it in the README and redo it when the interface changes.

verifiedThe committed recording with its commit and capture method stated.
