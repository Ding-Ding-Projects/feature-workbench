Extension download lifecycle

Gives every file the browser extension hands over a clear start, a live transfer and an honest finish, never claiming success early.

What it must do

  • Open a Start download dialog that names the file, source, destination and action before any data moves.
  • Switch to a separate Downloading surface whose Pause and Cancel operate the real transfer.
  • Show a non-blocking Download complete notice only after the transfer has truly finished.
  • Keep start and completion on top until resolved, and label browser demonstrations as demonstrations.

verifiedProof needed: One installed-extension transfer captured in all three states; injected markup or mocked messages do not count.

External editor handoff

Opens the file or folder you are looking at in your own code editor, and says plainly when none is installed.

What it must do

  • Detect installed editors, including per-user, system-wide, preview and portable installs of Visual Studio Code.
  • Let the person add or choose an editor, and remember that choice between sessions.
  • Open a single file, or a folder as the workspace root, in one action.
  • When no editor is found, say so plainly and offer a download instead of simulating a launch.

verifiedProof needed: A real launch from an installed build, the no-editor path, and a folder opened as a workspace.

file-converterpendingIncomplete

Offline file conversion and PDF tools

Converts documents, media, archives and data on this computer without going online, and keeps your originals untouched.

What it must do

  • Detect each file's type from a bounded read of its bytes, then offer searchable formats in eight categories.
  • Enable a format only when everything it needs is bundled and proven offline; list the rest as disabled, naming the missing component.
  • Write PDF split, merge, extract, reorder, rotate and metadata results atomically, then reopen them to verify.
  • Leave sources untouched, warn before lossy changes, and ask for strong confirmation before overwriting.
  • Process a queue of any length in fixed memory, with pause, resume, cancel, crash recovery and a storage check.

verifiedProof needed: Every category converting offline from bundled parts, outputs reopened, and a long queue in constant memory.

forge-publishingpendingIncomplete

Repository publishing workflow

Publishes a repository to the account you choose and confirms it really arrived before saying so.

What it must do

  • Let the person pick the account and owner from a searchable list with set active, refresh and sign out.
  • Support several signed-in accounts, each token kept only in the operating-system credential store.
  • Report sign-in, upload progress and failure honestly, then read the remote back before claiming success.
  • Offer copy-and-push where a provider cannot fork, and always say which route was taken.

verifiedProof needed: Several accounts at once, a publish read back from the remote, and no token in settings, data or exports.

Minecraft server creator and manager

Creates and runs a Minecraft server of any version, here or on a remote machine, with every setting as a real control.

What it must do

  • Discover every Java and Bedrock server version, past and current, plus development channels where they exist.
  • Tie configuration, commands, runtime and compatibility to the chosen version, and show gaps honestly.
  • Install flavours and plugins, then create and manage servers as a local process, local container, SSH process or SSH container.
  • Give every setting a typed control; a version picker beside a plain text editor is not full support.

verifiedProof needed: All four targets working in the built app, a version compatibility matrix, and install, manage and recovery runs.

Pre-generates a world with the exact server version you picked and saves it as a folder or ZIP where you choose.

ollama-suitependingIncomplete

Local Ollama model and runtime manager

Installs Ollama, shows which models suit your hardware, downloads them in a batch and lets you chat with them locally.

What it must do

  • Install Ollama in one click, recover a missing runtime, and respect existing installs and offline states.
  • List the whole official catalogue and every tag, marked stale or offline when it cannot refresh.
  • Give every variant an evidence-based fit: runs well, runs with limits, unlikely or unknown.
  • Use the selection only for batch pulls, reporting partial results; chat streams locally with attachments only where a model supports them.
  • Launch saved profiles from an allowlist with preview, snapshots, one-click restore and automatic rollback.

verifiedProof needed: A complete multi-page catalogue, all four fit verdicts on real hardware, and rollback after a failed launch.

progress-recoverycontrastPartial

Progress, cancellation and recovery

Shows how a long job is going where you started it, lets you stop it, and puts the fix beside whatever went wrong.

What it must do

  • Show the operation's real progress inside the dialog that started it, with its submit control disabled.
  • Block re-entry in the handler too, so a keyboard submit cannot start the work twice.
  • Offer slow optional steps as an explicit choice that names what skipping leaves undone.
  • Place recovery beside the control that failed, with sign-in on the spot for expired access and no work-losing remedies.
  • Report partial and failed outcomes distinctly from success.

verifiedProof needed: A keyboard submit that cannot re-enter, a declined optional step honoured, and captures of partial and failed states.
