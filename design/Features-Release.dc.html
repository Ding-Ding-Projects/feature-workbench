Clean build environment bootstrap

Every automated build starts from a clean machine and says exactly which missing tool stopped it.

What it must do

  • Keep a dependency list next to each workflow and check it before installing.
  • Install anything missing into job-local, cacheable locations.
  • Stop at the exact step that names the missing dependency.
  • Always upload safe outputs without hiding the original failure.

verifiedProof needed: A fresh-environment run that exercises the cache-miss path for every job.

Encrypted private-source build pipeline

Private projects get the same releases without their name or source ever appearing in public build records.

What it must do

  • Build private source on a public builder that holds only an encrypted, name-free payload.
  • Publish the release back to the private repository only.
  • If the builder is unavailable, stop with a clear blocker instead of an unencrypted fallback.

verifiedProof needed: A manual run by opaque id, with no private identifier in any public file.

Automated source line counts

Each release states how big the project is, counted by the release workflow rather than by hand.

What it must do

  • The release workflow counts lines with a committed script and records the command.
  • Separate source, tests and styles, with total and non-blank lines.
  • State exclusions, list generated files apart, and keep totals consistent.
  • Refresh the README figure only from a published release.

Source-bound release timing

Each release records exactly when its build started and finished, measured rather than guessed.

What it must do

  • Record workflow start, completion and duration in every release.
  • Use UTC ISO-8601 timestamps and a fixed HH:mm:ss duration.
  • Measure from the first job to publication; when unverified, say so instead of estimating.

verifiedProof needed: The three timing lines present and consistent with the run record.

Normal release automation

Every change becomes a real, downloadable release with its own tag and an honest note of what was checked.

What it must do

  • Each push or manual run builds, packages and publishes one new release.
  • Use a unique, increasing tag and attach the genuinely built installer.
  • Notes state which checks actually ran locally and their real results.
  • Publishing never triggers another run, and tokens are never printed.

verifiedProof needed: A unique tag per run and a downloadable installer on the release.

Verified build runner selection

Builds run on a machine that is actually available, so a job is never left waiting on one that is offline.

What it must do

  • Inspect available runners, their state, capacity and labels before dispatch.
  • Use a self-hosted runner only when it is genuinely available; else a pinned hosted image.
  • Never leave a job queued against an offline runner.

verifiedProof needed: Recorded inventory before dispatch, and no pull request trigger on self-hosted jobs.

Release food code names

Every release carries a dim sum code name beside its version, taken from the public catalogue and never reused.

What it must do

  • Pick only dishes whose public photo is published, using their exact English and Traditional Chinese names.
  • Use each code name once per project and record which release got which dish.
  • Show the code name and a photo link in the release notes, changelog, documentation site and About screen.
  • Keep the names factual at every humour level.
  • If the catalogue is unavailable, release on time with the version only.

verifiedProof needed: No reused code name, a recorded release-to-dish mapping, and alt text that names the dish.

Release food photograph

Release notes link to the dish's original photo in the public catalogue instead of carrying their own copy.

What it must do

  • Reference the original photo and catalogue entry with the dish's exact bilingual names.
  • Never keep copied photos or a second catalogue in this repository.
  • Never attach photos or photo archives to a release.
  • When no unused dish can be found, publish with the version alone and say so, without delay.

verifiedProof needed: Original-photo links with exact names, no copied or attached photos, and a visible version-only release when needed.
