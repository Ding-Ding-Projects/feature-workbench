Previewable batch actions

Lets a person select many items, preview what will happen to each, and run one action on all of them.

What it must do

  • Select with click, shift-click or keyboard in every list, including notifications and history.
  • Word select-all honestly: this page, or every match of the current filter; offer invert selection.
  • Show the exact count and a preview before running; report every skipped item and why.
  • Ask with two-key confirmation only for destructive batches; every batch stays undoable from history.

Searchable changelog

Shows every released version and what changed in it, searchable and filterable by date.

What it must do

  • List every released version with its date, grouped changes and a short commit link, reachable from Help.
  • Filter by a date range (picked or typed) and by pattern search; the two combine.
  • Copy or export exactly the filtered view, with its range and commits.
  • Keep entries factual; report invalid or partial dates inline without losing what was typed.

Faithful data exports

Saves a person's data in the format they choose, saying up front what each format keeps or drops.

What it must do

  • Offer every format that can faithfully carry the data, chosen per item.
  • State any loss before the export runs, and which formats can be imported back.
  • Record encoding, line endings and schema version in each file.
  • Leave out credentials and personal wording, and say so.

Local version history and recovery

Records every change on this device so any edit or deletion can be compared and undone.

What it must do

  • Keep an append-only local record of changes to tasks, rules and settings, labelled by what changed.
  • Make every restore a new revision, so a restore can itself be restored.
  • Browse, compare, filter by date and action, search, label, prune and export.
  • Never record a credential in plain form or bring back a secret that is no longer available; a history failure never blocks the person's own change.

verifiedA restore of a restore, combined filters, and recovery after a restart.

Non-blocking notification history

Reports results in small notices that never block work, and keeps them reviewable afterwards.

What it must do

  • Show information, success and progress as toasts in a bottom corner, never as a blocking dialog.
  • Let toasts close themselves, but keep errors and warnings until dismissed; stack without overlap.
  • Keep dismissed notices in a centre that can be searched and cleared in bulk.
  • Make every notice translated, announced, focusable and dismissible with a 44px target.

verifiedNo dialog for a non-decision, warnings that persist, and centre search and bulk dismiss.

Offline documentation reader

Puts every feature article inside the app, readable and searchable without a connection.

What it must do

  • Bundle every feature article at build time into a reader that works without a connection.
  • Render articles with the same formatter used elsewhere, and resolve article links inside the app.
  • Search titles and bodies, including pattern search.
  • Fail the build when an article is missing from the bundle.

Formatted provider responses

Shows release notes and other provider text as formatted, safely sandboxed content.

What it must do

  • Show release notes, issue and pull request bodies, commit messages and README previews as formatted text.
  • Use one shared formatter, isolated so the content never runs with the app's own permissions.
  • Resolve relative links against the source, and label the region for assistive technology.
  • Show an honest "no notes were provided" state when the source is empty.
